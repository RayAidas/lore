# 写作数据统计设计

> 状态：提议
> 范围：P1，小说级写作产出统计

## 目标与边界

Lore 已有章节字数、整书字数和单部小说的当日净增字数。本设计将其扩展为可回顾的日序列，让作者能够回答“这周写了多少”“最近是否持续写作”“每日目标完成得怎样”。

首期目标：

- 在小说概览显示今日、本周、连续写作天数和最近 7 天的日历式回顾。
- 在桌面右侧工具栏提供当前书库总体统计，并在活动 tab 属于小说章节时附加该小说统计。
- 统计按书库和小说隔离，并支持读取任意连续日期范围，为后续 28 天视图和全库首页复用。
- 保持编辑输入链路轻量，统计写入失败不影响编辑和保存。
- 以用户设备的本地自然日划分“今日”，避免 UTC 在东八区早晨切日。

首期不做：

- 写作时长、专注时段、速度、键盘输入量等行为监控。
- 云同步、跨设备合并、跨小说全库排行榜或社交比较。
- 将统计作为正文文件、书库元数据或导出内容的一部分。
- 根据外部编辑器、文件导入或历史版本恢复推断“写作量”。这些操作改变内容，但不能可靠归因给当前作者的写作行为。

## 术语与口径

| 名称 | 定义 |
| --- | --- |
| 当前字数 | 当前正文去空白 rune 的字数，沿用 `characterCountOf` 口径。 |
| 日净增 | 用户在 Lore 编辑器中对某小说章节造成的当前字数增量之和；可为负数。 |
| 有效写作日 | 日净增大于 0 的本地自然日；删除内容不计为写作日。 |
| 本周 | 以周一为首日、周日为末日的本地自然周。 |
| 每日目标 | 用户现有的全局每日净增目标；`0` 表示关闭目标。 |

日净增不是“写入硬盘的字数”，而是编辑器中已接受文本变化的净结果。撤销、删除和替换均会产生相反方向的增量。这样可即时反馈目标进度，并避免保存、自动保存和历史快照重复计数。

## 数据模型与存储

### 日期值对象

在 `lore_domain` 新增不可变 `WritingDay(year, month, day)`：

- 验证真实日历日期，提供 ISO `yyyy-MM-dd` 编解码和 `compareTo`。
- 不包含时区或时刻，不使用 `DateTime` 作为日键。
- 应用层在事件发生时用 `DateTime.now()` 的本地年月日构造它；测试直接传入值对象。

这与存储/历史记录继续使用 UTC 时间戳并不冲突：写作“日期”是面向用户的本地日历概念，历史“时间”是可排序的系统事件。

### 仓储端口

将当前只支持 `loadToday` 的端口替换为日期范围查询。示意接口如下：

```dart
abstract interface class WritingProgressRepository {
  Future<Map<WritingDay, int>> loadDailyDeltas(
    LibraryId libraryId,
    NovelId novelId, {
    required WritingDay fromInclusive,
    required WritingDay toInclusive,
  });

  Future<Map<WritingDay, int>> loadLibraryDailyDeltas(
    LibraryId libraryId, {
    required WritingDay fromInclusive,
    required WritingDay toInclusive,
  });

  Future<void> addDelta(
    LibraryId libraryId,
    NovelId novelId,
    WritingDay day,
    int delta,
  );

  Future<void> pruneBefore(LibraryId libraryId, WritingDay cutoffExclusive);
}
```

返回值只包含实际有记录的日期，调用者负责为日历补齐零值日期。`addDelta` 保持同一小说 key 的串行 read-modify-write，零增量不落盘。仓储不计算“本周”或“连续天数”，避免把展示策略耦合到平台存储。

`loadLibraryDailyDeltas` 只聚合当前书库已记录小说的日增量；它不读取正文，也不把不同书库的统计混合。“总体”在产品中始终指当前书库，而不是设备全局。

### 设备本地持久化

第一期继续由 `lore_platform_adapters` 的 SharedPreferences 实现，按 `LibraryId + NovelId` 分 key 存储，格式升级为：

```json
{
  "schemaVersion": 2,
  "dailyDeltas": {
    "2026-07-20": 1200,
    "2026-07-21": -80
  }
}
```

数据是可丢失、不可迁移的设备本地派生状态。保留最近 365 个本地自然日；启动时异步清理更早记录。这个上限足以支持年内回顾，同时避免 SharedPreferences 中每部小说的 JSON 无限制增长。需要跨设备历史或长期归档时，再迁移为专门的本地数据库并定义同步冲突规则。

v1 的 `counts` 是 UTC 日期键，且旧 key 不包含 `LibraryId`。首次用某小说记录/读取新 key 时，将该小说的旧 key 数据迁入当前书库；不能从缺失的原始时区反推本地日期，故键和值原样保留。迁移后新记录一律使用本地日期。迁移失败或格式错误按空统计恢复，绝不影响正文。

## 应用层投影

在 `lore_application` 新增 `WritingStatisticsService` 和只读投影：

```text
WritingStatistics
  todayNetDelta
  weekNetDelta
  activeDaysThisWeek
  currentStreakDays
  monthDays: List<DailyWritingStat>
    day, netDelta, goalProgress
```

服务分别提供 `computeLibrary` 与 `computeNovel`，接收 `LibraryId`、可选 `NovelId`、今日 `WritingDay`、展示月份与每日目标。它一次读取该月和向前计算连续天数所需的最多 365 天记录，并完成以下纯计算：

- 今日：今日键的净增，缺失为 0。
- 本周：本周 7 个键的求和。
- 活跃天数：本周中净增大于 0 的日期数。
- 连续天数：从今日向前连续净增大于 0 的天数；今天没有写作时为 0，不把昨天的连续状态伪装成仍在持续。
- 月历：按日期升序返回展示月份的全部日期，缺失日期补 `0`。

`NovelOverview` 组合小说投影，仍单独保留结构性统计（总字数、卷数、章节数）。右侧统计面板直接使用书库投影和可选的小说投影。这避免小说概览服务继续膨胀，也允许未来首页直接复用写作统计服务。

## 事件与一致性

1. 编辑器防抖后的统计更新计算 `nextCharacterCount - document.characterCount`。
2. 若章节属于已注册小说，以当前书库 ID、小说 ID 和设备本地日期调用 `addDelta`；同一批变更只计一次。
3. 数据写入采用 fire-and-forget。失败不阻塞输入、保存或自动保存；下次写入仍可继续。
4. 小说概览每次重新进入或内容树 revision 更新时重载统计。首期不要求编辑中打开的概览实时刷新；后续可用 `ValueNotifier`/Riverpod 状态订阅补上。

外部文件变动、导入、reconcile 和历史恢复会刷新正文总字数缓存，但不写入日净增。这是有意的归因边界，避免把同步、批量替换或恢复历史误计为写作成果。

## 界面

### 小说概览

小说概览现有的统计区扩展为两个全宽分区：

1. 概览指标：总字数、章节数、卷数保留第一行；第二行显示“今日净增”“本周净增”“连续写作”。
2. 写作进度：保留每日目标进度，补充“本周活跃 X/7 天”；下方显示当月日历摘要。

### 右侧统计面板

在现有 `WorkspaceInspector` 中新增与“助手 / 大纲 / 版本 / 信息”平级的“统计”tab，使用 `Icons.bar_chart_outlined`。它只在桌面端、工具栏可见的现有条件下展示；Android 不强行压缩该面板，未来由首页承载同一份书库统计。

面板按滚动区域从上至下展示：

```text
写作统计                         [上月] 2026 年 7 月 [下月]

当前书库
今日 +1,200   本周 +4,850   连续 5 天
本周活跃 4 / 7 天

日历
一   二   三   四   五   六   日
29  30   1    2    3    4    5
         +800 +0   +1,200        
6   7    8    9   10   11   12
+500     +900 ...

当前小说：星海
今日 +800     本周 +2,100    连续 3 天
```

- “当前书库”始终显示，即使没有打开文档；它是所有已记录小说的日净增聚合。
- “当前小说”仅在焦点编辑组的活动 tab 能解析到注册小说时显示。普通文件、未打开 tab、非小说正文或无法解析归属时，整个区块不渲染，不显示空卡片或“无数据”占位。
- 分屏时依据当前焦点编辑组的活动 tab，焦点切换即刷新小说区块；书库总体不变。
- 月份标题两侧使用仅图标的上一月/下一月按钮，并带 tooltip。默认打开当前本地月；切换只改变日历，不改变“今日 / 本周 / 连续写作”摘要口径。

### 日历样式

日历替代柱状趋势图。每个日期单元是稳定高度的可点击区域：上方为日期号，下方为该日净增，正数显式带 `+`、负数带 `-`，零值显示 `0`，无记录显示短横线。窄面板用 `1.2k` 等紧凑单位，宽度足够时显示完整数值。今天有清晰边框，选中日期显示轻量背景；颜色只作辅助，正值、负值、零值和无记录可从文本读出。

点击某天后，在日历下方显示该日期的书库净增、当前小说净增（适用时）及每日目标完成情况。未来若记录写作会话，可在此处扩展，不改变日历网格。非本月的补位日期仅显示日期，不显示统计数。

日历使用 `GridView` 或固定七列 `Table`，不引入图表依赖。右侧面板宽度可在既有 240--480 px 内调整；日格用固定最小高度与截断/紧凑数值保证不溢出。小说概览中的月历在窄屏可变为仅当前周和“查看完整统计”入口，桌面则展示完整月历。每日目标为 0 时，保留日历与周数据，只显示“未设置每日目标”，不显示伪进度。

首期不新增其他全局导航入口。未来 Android 首页复用 `WritingStatisticsService`，但不复用桌面 inspector 的三栏交互。

## 测试与验收

领域/应用测试：

- 月历补位、缺失日期、负值、跨周、周一/周日边界的汇总结果。
- 连续天数在今天未写、今天写过、昨天中断时的结果。
- 目标关闭、目标完成和超额完成的投影。

平台适配测试：

- v1 JSON 平滑迁移、书库隔离、损坏 JSON 容错、小说/书库范围查询和 365 天清理。
- 并发 `addDelta` 不丢失增量，负数增量正确累加。

应用/Widget 测试：

- 编辑章节产生一次正确的本地日增量；非小说文件和外部刷新不产生记录。
- 右侧统计 tab 显示书库摘要；焦点 tab 属于小说时显示小说区块，其他情况下不渲染该区块。
- 日历显示日期、正负净增、零值、无记录、今天和选中日期的语义标签；月份切换不改变摘要口径。
- 窄宽布局无溢出，颜色以外仍能读出正负值与日期。

完成标准：用户在任一小说编辑后，能在概览和右侧面板中看到与编辑器字数变化一致的今日和本周净增；中国时区在本地 00:00 而非 08:00 切换日统计；连续写作和当月日历数据在应用重启后仍可查看。

## 分阶段实施

1. 增加 `WritingDay`、升级仓储端口/SharedPreferences schema，并覆盖迁移与日范围测试。
2. 实现应用层统计投影与纯计算测试，接入 `NovelOverviewService`。
3. 将编辑事件改用本地 `WritingDay`，移除现有 UTC `loadToday` 依赖。
4. 新增右侧统计 inspector、扩展小说概览月历摘要与 widget 测试，最后运行相关包测试、`flutter analyze` 和全量脚本。
