# 书库存储详细设计

> 文档状态：初稿  
> 依赖文档：[书库与内容模型](library-and-content-model.md)、[技术架构设计](technical-architecture.md)

## 设计目标

- TXT、Markdown 和附件始终是用户可直接访问的真实文件。
- 小说、正文、卷和章拥有稳定身份，不完全依赖文件名和路径。
- 用户从系统文件管理器修改内容后，Lore 能够重新协调结构。
- 书库整体复制到另一台设备后仍保留小说和卷章信息。
- 搜索索引、本机界面状态等派生数据可以随时删除并重建。
- 保存过程中应用崩溃时，优先保证正文不丢失，其次保证元数据可修复。

## 数据分类

### 权威内容

权威内容决定用户作品本身：

- TXT、Markdown 正文和资料。
- 文件夹结构。
- 图片及其他附件。
- 书库和小说目录中的 JSON 元数据。
- 模板、历史快照和回收站内容。

权威内容保存在书库中，应随书库备份和迁移。

### 本机状态

本机状态只描述当前设备上的使用情况：

- 最近打开和标签页。
- 窗口大小、侧栏宽度和面板开关。
- macOS 路径或 Android SAF 授权句柄。
- 当前设备上的编辑器光标和临时草稿恢复信息。

本机状态保存在应用私有目录，不要求随书库迁移。

### 可重建数据

- SQLite 全文搜索索引。
- 文件扫描缓存。
- 字数、章节数和 Markdown 解析缓存。
- 缩略图和封面缓存。

可重建数据保存在应用私有目录。删除后只影响性能，不影响内容正确性。

## 书库目录结构

```text
书库/
├── .lore/
│   ├── library.json
│   ├── templates/
│   ├── history/
│   ├── trash/
│   └── recovery/
├── 长夜行/
│   ├── .lore/
│   │   ├── novel.json
│   │   └── content.json
│   ├── 正文/
│   ├── 大纲.md
│   └── 人物/
└── 随笔/
```

`.lore` 默认在 Lore 文件树中隐藏，但用户可通过系统文件管理器查看。应用不得依赖操作系统真正隐藏该目录。

## 标识符

### ID 格式

- 书库、小说、正文、卷、章和模板均使用 UUID v4。
- ID 创建后不因重命名、移动或重新排序改变。
- ID 只保存在 Lore 元数据中，不强制写入 TXT 或 Markdown。
- 复制小说时默认生成新的小说和内容 ID，避免同一书库出现身份冲突。
- 导入另一个完整小说目录时，如果 ID 与当前书库冲突，需要执行重新标识流程。

### 路径格式

- 元数据中只保存相对书库或相对小说目录的标准化路径。
- JSON 中统一使用 `/` 作为逻辑分隔符，不保存平台绝对路径。
- 路径比较是否区分大小写由存储后端报告，业务层不得自行假设。
- 禁止在元数据中保存 `..` 等能够逃出作用域的路径。

## 书库清单

书库根级 `.lore/library.json` 保存可移植的书库身份、格式版本和小说注册信息。

建议结构：

```json
{
  "schemaVersion": 1,
  "libraryId": "7ad6726f-e74f-462d-8584-5bd2e95cd8b5",
  "createdAt": "2026-07-17T10:00:00Z",
  "updatedAt": "2026-07-17T10:00:00Z",
  "novels": [
    {
      "id": "16573e71-837e-427b-b62b-4764eb228d75",
      "path": "长夜行"
    }
  ],
  "templates": []
}
```

约束：

- `schemaVersion` 用于迁移，不等同于应用版本。
- `novels` 只作为快速入口，小说目录内的 `novel.json` 是小说身份的主要证明。
- 扫描发现未注册但包含有效 `novel.json` 的目录时，可提示用户恢复注册。
- 注册项指向的目录不存在时，先标记缺失，不立即删除记录。

应用级主题、窗口和最近打开记录不写入 `library.json`。这类数据属于本机状态或独立设置。

## 小说清单

小说目录内 `.lore/novel.json` 保存小说自身信息。

```json
{
  "schemaVersion": 1,
  "novelId": "16573e71-837e-427b-b62b-4764eb228d75",
  "title": "长夜行",
  "description": "",
  "cover": null,
  "body": {
    "id": "26e84025-7056-48e7-b83d-7a0ea6497e5c",
    "path": "正文"
  },
  "chapterFormat": "markdown",
  "numberingMode": "continuous",
  "createdAt": "2026-07-17T10:00:00Z",
  "updatedAt": "2026-07-17T10:00:00Z"
}
```

字段说明：

- `title` 是产品中的小说显示名称，默认与目录名一致，但允许目录重命名后独立修复。
- `cover` 保存相对小说目录的路径或 `null`。
- `body.path` 保存正文目录的相对路径，正文目录重命名后更新该字段。
- `chapterFormat` 为新建章节默认格式，可取 `text` 或 `markdown`。
- `numberingMode` 可取 `continuous` 或 `perVolume`。

小说概览中的字数、卷数、章数和本周统计不写入此文件作为权威数据。它们由文件和本地数据库计算，必要时可建立带时间戳的缓存。

## 正文内容树

`.lore/content.json` 保存卷章身份、路径、排序和编号语义。

```json
{
  "schemaVersion": 1,
  "novelId": "16573e71-837e-427b-b62b-4764eb228d75",
  "revision": 12,
  "nodes": [
    {
      "id": "37a6439c-a995-4420-ab98-ea3e743c8ea7",
      "type": "chapter",
      "parentId": "26e84025-7056-48e7-b83d-7a0ea6497e5c",
      "path": "正文/序章.md",
      "order": 1000,
      "number": null,
      "role": "prologue"
    },
    {
      "id": "f1954de1-67dd-43f5-a0e1-97a57dfe744a",
      "type": "volume",
      "parentId": "26e84025-7056-48e7-b83d-7a0ea6497e5c",
      "path": "正文/第一卷",
      "order": 2000,
      "number": 1,
      "role": "normal"
    },
    {
      "id": "898f5aeb-166b-4aaf-bd97-bf7f2b56d15a",
      "type": "chapter",
      "parentId": "f1954de1-67dd-43f5-a0e1-97a57dfe744a",
      "path": "正文/第一卷/第1章.md",
      "order": 1000,
      "number": 1,
      "role": "normal"
    }
  ]
}
```

### 节点类型

- `volume`：正文目录的直接子文件夹。
- `chapter`：正文目录或卷目录下的 TXT、Markdown 文件。

正文目录本身由 `novel.json` 描述，不重复加入 `nodes`。

### 排序字段

- `order` 只需在同一个 `parentId` 下有序。
- 初始值以 1000 为步长分配，便于在两个节点之间插入。
- 没有可用间隔时，仅对同级节点重新归一化为 1000、2000、3000。
- 修改 `order` 不自动修改 `path`、`number` 或文件名。
- 整书阅读顺序由正文直属节点的顺序和各卷内部章节顺序共同计算。

### 编号与角色

- `number` 表达逻辑编号，不负责决定排序。
- `role` 初期可取 `normal`、`prologue`、`epilogue`、`extra`。
- 序章、后记和番外可将 `number` 设为 `null`。
- “根据当前顺序重新编号”只更新符合条件节点的 `number`，之后再由独立预览确认是否重命名文件。

### 显示名称

卷章显示名称默认来自文件或目录名，不在 `content.json` 重复保存。未来如需别名，应增加明确字段而不是隐式覆盖路径名称。

## 自动识别与协调

### 首次扫描

打开书库时按以下顺序处理：

1. 读取 `library.json`。
2. 验证已注册小说目录和 `novel.json`。
3. 验证正文目录。
4. 扫描正文第一层文件夹和 TXT、Markdown 文件。
5. 扫描各卷内的 TXT、Markdown 文件。
6. 与 `content.json` 对比并生成协调计划。
7. 对无歧义变更自动修复，对高风险变更请求确认。

### 新对象

- 正文目录新增直接子文件夹时，识别为卷并生成新 ID。
- 正文目录新增 TXT、Markdown 文件时，识别为未分卷章节并生成新 ID。
- 卷内新增 TXT、Markdown 文件时，识别为章节并生成新 ID。
- 新节点默认追加到同级末尾，除非由应用内明确插入到指定位置。

### 重命名与移动恢复

应用内操作拥有明确节点 ID，可直接更新路径而不改变身份。

外部操作按以下证据尝试匹配：

1. 平台提供且仍有效的文件标识。
2. 同一扫描批次中唯一的旧节点消失与新路径出现组合。
3. 文件大小、修改时间和快速内容指纹。
4. 完整内容哈希，仅在必要时计算。

如果多个候选同样可信，不能自动合并，应保留现状并提示用户选择。

### 类型变化

- 章节从卷移动到正文目录后，仍为同一章节，只更新 `parentId` 和路径。
- 文件移出正文结构后，提示是否转为普通文件；确认后从 `content.json` 移除，但不删除真实文件。
- 普通 TXT、Markdown 文件移入正文结构后，提示并注册为章节。
- 卷移出正文目录后，提示是否转为普通文件夹。
- 不支持的文件格式进入正文目录时保留为普通资源，不加入内容树。

## 文件编码与换行

- 新建 TXT、Markdown 默认使用 UTF-8，不写 BOM。
- 读取时识别 UTF-8 BOM，并在导入场景尝试检测常见中文编码。
- 无法可靠识别编码时要求用户选择，不静默用错误编码覆盖。
- 保存时默认保留原文件换行风格，用户明确转换时除外。
- 读取时记录原编码和换行信息，但该记录属于本机文档状态，不作为小说结构元数据。

## 保存事务

### 普通正文保存

正文保存不要求同步提交 `content.json`，因为内容变化不改变结构：

1. 从编辑器取得不可变文本快照。
2. 写入同目录临时文件或存储后端提供的安全替换目标。
3. 刷新并替换原文件。
4. 更新编辑器已保存版本号。
5. 异步发布 `DocumentSaved`，更新索引、统计和历史策略。

如果存储后端不支持可靠的原子替换，采用“备份原文件—写入新内容—验证—清理备份”的降级流程。

### 结构操作

创建、移动、重排或删除卷章需要同时修改文件系统和元数据：

1. 验证权限、名称冲突和目标结构是否合法。
2. 将操作意图写入 `.lore/recovery/pending-operation.json`。
3. 执行文件系统操作。
4. 写入新的 `content.json` 临时文件并替换旧文件。
5. 清除 pending 操作。
6. 异步更新本地缓存和搜索索引。

`pending-operation.json` 只允许存在一个前台结构事务。大型导入使用独立任务清单，不长期占用该文件。

### 崩溃恢复

启动时若发现 pending 操作：

- 比较操作前后文件状态和元数据 `revision`。
- 已完成文件操作但元数据未提交时，根据操作意图补交元数据。
- 文件操作未完成时，回滚临时对象或恢复备份。
- 无法自动判断时停止结构写操作，提供恢复副本和人工选择。

正文始终优先保留，不以恢复元数据为理由删除无法识别的用户文件。

## 自动保存与并发

- 每个打开文档维护递增的编辑版本和已保存版本。
- 自动保存使用防抖触发，但同一文档同一时间只允许一个保存任务。
- 保存期间继续输入时，当前快照保存完成后继续保存最新版本，不丢弃新编辑。
- 文件外部修改时，如果编辑器无未保存内容，可自动重新加载并提示。
- 文件外部修改且编辑器存在未保存内容时，进入冲突状态，保留本地缓冲区和磁盘版本。
- 不通过“最后写入者获胜”静默覆盖冲突。

## 历史版本

- 历史快照保存在书库 `.lore/history/`，以文档稳定 ID 组织。
- 快照记录原相对路径、创建时间、内容哈希和触发原因。
- 小型文本可保存完整压缩快照；增量存储方案在性能验证后决定。
- 恢复历史版本时先为当前内容创建快照。
- 文档移动后历史仍通过稳定 ID 关联。

建议结构：

```text
.lore/history/
└── 898f5aeb-166b-4aaf-bd97-bf7f2b56d15a/
    ├── manifest.json
    └── snapshots/
```

## 回收站

- 应用内删除的内容移动到 `.lore/trash/`，而不是立即永久删除。
- 回收站清单记录原路径、节点 ID、删除时间和对象类型。
- 删除卷时保留整个目录结构和内部章节身份。
- 恢复路径冲突时由用户选择重命名或新位置。
- 外部系统直接删除的文件无法保证进入 Lore 回收站，只能通过历史或备份恢复。

## 本地 SQLite

SQLite 保存在应用私有目录，并以 `libraryId` 区分当前书库缓存。建议包含：

- 文件扫描状态。
- 全文搜索内容和分词索引。
- 字数、修改时间和内容哈希缓存。
- 最近打开、光标位置和阅读位置等本机状态。
- 后台任务状态。

数据库必须支持：

- 根据当前书库完整重建。
- 检测 `libraryId` 变化并避免错误复用旧索引。
- 应用升级时独立迁移。
- 损坏后自动隔离并重建，不阻止用户打开正文。

## 元数据版本迁移

- 每个 JSON 文件独立保存 `schemaVersion`。
- 迁移前创建元数据备份。
- 迁移采用逐版本升级，不直接假设可以从任意旧版本跳到最新结构。
- 应用遇到高于自身支持范围的版本时，以只读方式打开或拒绝结构写操作，避免降级破坏。
- 迁移失败时保留原文件和错误报告，不修改正文。

## 安全限制

- 所有相对路径在执行前进行规范化和作用域校验。
- 禁止模板、导入清单或未来 AI 工具访问书库之外的路径。
- `.lore` 中不保存 API Key 和其他账号凭据。
- 日志使用对象 ID 和相对路径，默认不记录正文内容。
- 临时文件和恢复副本不得使用可预测的共享目录文件名。

## 首轮实现范围

首轮只实现形成完整闭环所需的数据能力：

- 创建和打开单一书库。
- 创建、注册和扫描小说。
- 创建正文、卷和章。
- 保存 `library.json`、`novel.json` 和 `content.json`。
- 在应用内完成重命名、移动、排序和删除。
- 检测基础外部新增、删除和重命名。
- 正文安全保存和崩溃恢复。
- SQLite 搜索索引可重建骨架。

哈希优化、复杂同步冲突和跨文档提供者兼容策略在技术验证后逐步补充。

## 当前实现状态

- macOS 通过原生 MethodChannel 和 security-scoped bookmark 持久化书库目录授权。
- 新目录经过用户确认后，仅初始化 `.lore/library.json`，其他内部目录按功能需要创建。
- 授权切换采用 pending/commit 两阶段，新目录成功打开前保留原书库授权。
- 本地 repository 已支持 manifest 校验、独占初始化、真实路径越界防护和懒加载目录列表。
- 普通文件已支持创建、重命名、UTF-8/BOM 读取、换行风格保留和基于 revision 的安全保存。
- 工作区已支持多标签、800ms 防抖自动保存、外部修改冲突防覆盖和本机会话恢复。
- Android 当前返回明确的平台未支持状态，后续在同一 Application 接口下实现 SAF。
