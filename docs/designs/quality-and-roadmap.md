# 质量要求与路线图

## 非功能需求

### 性能

- 普通编辑操作应保持即时响应。
- 大型书库搜索和索引不得阻塞编辑器。
- 长章节输入时避免全量重新解析和渲染。
- 桌面端和移动端均控制内存占用，按需加载未打开文档。

### 可靠性

- 文件写入尽量使用临时文件与原子替换，降低损坏风险。
- 元数据更新失败不得影响正文文件读取。
- 应用异常退出后可恢复最近编辑状态。
- 所有派生状态都应能够从真实文件或历史记录重建。

### 隐私与安全

- 默认不上传用户内容。
- 未来调用 AI 时明确标识数据将发送给第三方模型服务。
- API Key 不记录在日志中。
- 日志默认避免包含完整正文。

### 可访问性

- 支持系统字体缩放和高对比度需求。
- 关键操作支持键盘快捷键。
- 不仅依赖颜色表达保存、冲突和错误状态。

## 第一阶段目标

第一阶段需要验证三个核心体验：

1. 用户愿意长时间在 Lore 中写作。
2. 用户愿意将作品和相关资料放入书库。
3. 用户能够安全迁移、管理和导出已有作品。

## MVP 范围

### 包含

- 单书库及真实文件系统管理。
- 新建、导入和管理小说。
- 正文、卷、章结构及排序。
- 普通文件夹、TXT、Markdown 文件管理。
- 多标签页编辑。
- 自动保存与基础历史版本。
- TXT 和 Markdown 编辑、预览。
- 小说、正文和卷概览。
- 基础沉浸写作模式、主题和排版配置。
- 当前章、当前卷和整书阅读模式。
- 模板系统。
- 全文搜索。
- 回收站。
- 小说合并导出为 TXT、Markdown。
- macOS 优先实现，并完成 Android 核心写作与阅读适配。

### 暂不包含

- AI Agent。
- 官方云同步。
- 多人实时协作。
- 社区、作品发布和网文平台直传。
- 完整插件系统。
- Canvas、白板和复杂知识图谱。
- 多 Agent 编排。
- Windows、Linux 和 iOS 的深度适配。
- 复杂 Markdown 所见即所得编辑器。

## 建议开发顺序

1. 建立 Flutter 工程与跨平台基础架构。
2. 实现书库、文件系统访问和元数据模型。
3. 实现小说、正文、卷、章的创建与管理。
4. 实现 TXT、Markdown 编辑器和多标签页。
5. 实现自动保存、历史版本和异常恢复。
6. 实现小说、正文和卷概览。
7. 实现沉浸写作、主题与排版设置。
8. 实现章节、卷和整书阅读模式。
9. 实现模板、全文搜索和回收站。
10. 实现导入、导出和迁移工具。
11. 完成 Android 输入、后台保存和阅读适配。
12. 基础体验稳定后设计并实现 AI Agent。

## 后续待细化事项

- Android 不同 SAF 文档提供者的兼容性和降级策略。
- 文件在外部同时移动并修改时的身份恢复准确性。
- 章节批注在正文修改后的锚点算法。
- Markdown 编辑器组件和增量解析方案。
- 历史快照的触发条件、压缩方式与清理策略。
- 搜索索引技术选型及中文分词策略。
- 模板实例化时的命名冲突和变量输入交互。
- 导入大 TXT 时的章节标题识别规则。
- 未来跨端同步的协议与冲突解决界面。
- 正式视觉语言、品牌名称、图标和主题规范。
