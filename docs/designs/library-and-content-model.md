# 书库与内容模型

## 单书库模式

- Lore 只管理一个书库。
- 书库对应一个真实本地目录。
- 应用启动后直接进入该书库，不设计多书库切换功能。
- 支持将已有文件、文件夹和小说导入书库，方便迁移。

```text
我的书库/
├── .lore/
├── 长夜行/
├── 另一部小说/
├── 随笔/
└── 阅读摘录.md
```

## 小说结构

新建小说时，用户输入书名。确认后在书库根目录创建同名文件夹、注册小说元数据，并自动创建正文目录。

```text
长夜行/
├── .lore/
├── 正文/
│   ├── 序章.md
│   ├── 第一卷/
│   │   ├── 第1章.md
│   │   └── 第2章.md
│   ├── 第二卷/
│   │   └── 第3章.md
│   └── 后记.md
├── 大纲.md
├── 人物/
├── 世界观/
└── 灵感.txt
```

正文目录之外的所有内容均由用户自由组织，不自动识别为卷或章。

## 正文识别规则

- 每部小说同一时间只能有一个正文目录。
- 正文目录默认名称为“正文”，同时通过稳定 ID 和元数据识别，不能只依赖名称。
- 正文目录的直接子文件夹识别为卷。
- 正文目录下的直接 TXT、Markdown 文件识别为未分卷章节。
- 卷目录下的 TXT、Markdown 文件识别为章节。
- 图片、音频及其他格式文件不识别为章节。
- 卷内暂不支持嵌套子卷；卷内其他文件夹默认不参与卷章结构。
- 文件被拖入或拖出正文结构时，应提示是否改变其对象类型。

## 创建流程

### 新建小说

1. 用户点击“新建小说”。
2. 弹窗要求输入书名。
3. 在书库根目录创建小说同名文件夹。
4. 创建并注册正文目录。
5. 初始化小说元数据。
6. 打开小说概览页。

若存在同名目录，提供以下选择：

- 将现有文件夹设为小说。
- 修改新小说名称。
- 取消创建。

### 新建卷

- 不要求用户输入名称。
- 默认按照现有卷最大序号递增，生成“第一卷”“第二卷”等名称。
- 创建后允许重命名，例如“第一卷 初入江湖”。
- 卷序号、显示名称和排序分别保存，不能完全依赖文件名推断。

### 新建章

- 不要求用户输入名称。
- 默认生成“第1章”“第2章”等名称。
- 默认文件格式可在设置中选择 TXT 或 Markdown。
- 创建后立即打开并聚焦编辑器。
- 章节允许重命名，例如“第1章 雨夜”。

## 排序与编号

- 卷和章使用稳定 ID 标识。
- 阅读顺序、导出顺序和 AI 上下文顺序使用显式排序字段。
- 用户拖动卷章时只改变内部顺序，不自动批量修改文件名。
- 用户可主动执行“根据当前顺序重新编号”。
- 支持全书连续编号和每卷重新编号两种模式。
- 序章、番外、后记等特殊章节可以不占用普通章节编号。
- 正文直属章节和卷可以混合排序，以表达“序章 → 第一卷 → 第二卷 → 后记”等结构。

## 元数据设计

元数据采用书库级和小说级结合的方式保存。元数据不得污染 TXT 正文；Markdown 文件也不强制写入 Lore 私有字段。

```text
书库/
├── .lore/
│   ├── library.json
│   ├── templates/
│   ├── history/
│   ├── trash/
│   └── recovery/
└── 长夜行/
    ├── .lore/
    │   ├── novel.json
    │   └── content.json
    └── 正文/
```

### 书库级元数据

- 书库版本与迁移信息。
- 小说注册信息。
- 模板注册信息。
- 历史版本和回收站信息。

### 小说级元数据

- 小说稳定 ID、书名、简介和封面。
- 正文目录稳定 ID。
- 卷、章的稳定 ID、类型、顺序和编号信息。
- 小说字数、章节数等可重建统计信息。章节字数（`characterCount`）作为持久化缓存写回 `content.json` 加速启动，仍可重算覆盖。
- 小说独立的写作、阅读和导出设置。

### 本机数据库

- SQLite 搜索索引、最近打开、标签页、光标和扫描缓存保存在应用私有目录。
- Android SAF 书库不能被当作普通文件路径直接运行 SQLite。
- 本机数据库属于可重建数据，不随书库迁移，不得成为正文或小说结构的权威来源。

### 外部文件变更

- 监听用户通过系统文件管理器进行的新增、删除、移动和重命名操作。
- 优先通过稳定 ID 和文件特征恢复对象关联。
- 无法确定语义时提示用户确认，不进行高风险自动推断。
- 元数据丢失时允许重新指定小说和正文目录。
- 搜索索引损坏或删除后能够从真实文件重建。
