# 产品总览

> 文档状态：初稿  
> 当前阶段：产品定义  
> 优先平台：macOS、Android  
> 技术方向：Flutter

## 产品定位

Lore 是一款面向网文写作者的本地优先写作软件，同时支持桌面端和移动端。产品以沉浸式写作为核心，兼顾小说阅读体验、开放的书库管理方式，并在后续集成可读取和操作书库内容的 AI Agent。

Lore 不是一个附带小说功能的通用笔记软件，也不照搬 Obsidian 的全部功能。产品只借鉴其“内容由真实文件夹和文件组成”的设计思想，让作者能够使用自己的方式组织正文、资料、随笔和灵感。

产品核心理念：

> 写作是核心，阅读是校验方式，书库是长期记忆，AI 是可控的创作协作者。

## 目标用户

### 核心用户

- 进行长篇、连载或系列小说创作的网文作者。
- 需要同时管理正文和大量创作资料的作者。
- 重视长时间写作舒适度和跨设备体验的用户。
- 希望使用 AI 校对、分析和整理作品，但不希望失去内容控制权的作者。

### 核心需求

- 长时间写作时界面简洁、舒适、不易疲劳。
- 卷章结构清晰，能够快速创建、移动和连续阅读章节。
- 正文与大纲、人物、设定、灵感等资料互不干扰。
- 内容以开放文件格式保存在本地，便于迁移和备份。
- Mac 和 Android 上均能获得适合设备形态的交互体验。
- 后续可使用用户自己的模型 API Key 启用 AI 能力。

## 产品原则

### 本地优先

- 用户内容首先保存在本地，无网络时仍可完整使用核心功能。
- 正文使用 TXT 或 Markdown 等开放格式，不依赖 Lore 才能读取。
- 索引、缓存等派生数据必须可以重建，不能成为内容的唯一来源。

### 万物皆文件

- 书库中的主要内容均对应真实文件夹或文件。
- 小说、正文、卷和章仍是文件系统对象，只是额外具有产品语义和元数据。
- 用户可以通过 Finder、系统文件管理器、Git 或其他编辑器访问内容。

### 约定正文，自由组织资料

- Lore 只对小说、正文、卷和章提供必要的特殊处理。
- 不强制创建大纲、人物、世界观、时间线、灵感等预设目录。
- 小说正文之外的资料由作者自行建立文件夹和文件组织。
- 模板用于满足不同作者的个性化工作流，而不是规定统一流程。

### 写作体验优先

- 优先保证输入稳定性、长文性能、输入法兼容性和自动保存可靠性。
- 复杂富文本效果不得影响持续写作体验。
- AI、知识关联等高级功能不能干扰基础写作流程。

### 用户掌控

- 不静默修改、移动或删除用户内容。
- 可能改变内容语义的操作需要明确提示。
- 后续 AI 写操作必须展示差异并由用户确认。

## 核心术语

| 术语 | 定义 |
| --- | --- |
| 书库 | Lore 管理的唯一工作空间，对应一个真实本地目录 |
| 小说 | 注册了小说元数据的根级文件夹 |
| 正文 | 小说中唯一的特殊正文目录，默认名称为“正文” |
| 卷 | 正文目录下注册为卷的直接子文件夹 |
| 章 | 正文目录或卷目录下注册为章节的 TXT、Markdown 文件 |
| 普通文件夹 | 不参与小说卷章结构的文件夹 |
| 普通文件 | 不参与小说卷章结构的文件 |
| 模板 | 可用于快速复制并创建内容的文件、文件夹或特殊对象结构 |
